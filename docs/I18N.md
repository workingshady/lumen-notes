# Interface languages (i18n) and RTL

Lumen's interface ships in **English** and **Arabic (العربية)**. Note content is never translated: it keeps its own per-block direction (`dir="auto"`, see `src/lib/markdown.ts`).

- Module: `src/lib/i18n.ts`. Catalog: `src/i18n/ar.ts` (merges the area files in `src/i18n/ar/*.ts`).
- Setting: **Settings › Appearance › Language** = English / العربية / Auto (Auto = `navigator.language`), and **Numbers** = Western `0123` (default) / Arabic-Indic `٠١٢٣`. Stored in the `lumen.settings` object (`lang`, `digits`) on this device. Switching is live (no reload).
- Direction follows the language: `i18n.ts` sets `<html lang dir data-digits>`. The round-2 `ws-dir.tsx` (`tr`, `num`, `useRtl`, `setUiDir`) is now a thin layer over it.
- Test: `npx tsx scripts/i18n.test.ts` (plural rules, interpolation, fallback, and a **coverage report**: every literal key used in `t()`/`tx()`/`tk()`/`tr()` must have an Arabic entry; the missing count must be 0).

## Adding a string

```tsx
import { t, tx, tk, fmtNum, fmtDate, fmtRelative, useLang } from "../lib/i18n";

<button title={t("Copy link")}>{t("Share")}</button>
t("{done} of {total} done", { done, total })            // interpolation; numbers follow the digits setting
t("{n} card due|{n} cards due", { n })                  // English plural: "one|other"; pass n (or count)
tx("Delete {name}?", { name: <b>{title}</b> })          // React nodes as values
const TABS = [{ id: "list", label: tk("List") }];       // module constants: mark with tk(), render with t(tab.label)
fmtDate(note.updatedAt)                                 // 19 Nov 2026 / ١٩ نوفمبر ٢٠٢٦ (Arabic month names, Gregorian)
fmtRelative(ts)                                         // "2 minutes ago" / "قبل دقيقتين"
```

Then add the Arabic in the matching area file of `src/i18n/ar/` (keys are the exact English source):

```ts
"Copy link": "نسخ الرابط",
"{done} of {total} done": "أُنجز {done} من {total}",
"{n} card due|{n} cards due": { zero: "لا بطاقات مستحقة", one: "بطاقة واحدة مستحقة", two: "بطاقتان مستحقتان", few: "{n} بطاقات مستحقة", many: "{n} بطاقة مستحقة", other: "{n} بطاقة مستحقة" },
```

Rules:
- The key is a **string literal** in the call (no concatenation, no template with `${}`), otherwise the coverage check can't see it. Build sentences with `{placeholders}`, never by joining translated fragments (word order differs in Arabic).
- Arabic plurals have six categories (`Intl.PluralRules("ar")`: zero 0, one 1, two 2, few 3–10, many 11–99, other 100+). Give at least `other`; give `zero/one/two` when the sentence reads better without the number ("ملاحظتان", not "2 ملاحظة").
- Missing key → English (never a blank). Missing placeholder value → the `{name}` stays visible.
- Don't shadow `t` (e.g. `.map((t) => …)`) in a scope that calls `t()`.
- Components re-render on a language change because `App` subscribes with `useLang()`; a `memo()` component that shows text must call `useLang()` itself.
- Don't translate: note titles and any user content, tag names, property keys stored in front-matter, Markdown syntax, keyboard shortcuts, values used in logic, the dev panel (`?dev=panel`, developer-only).

## Adding a language
1. Add the code to `Lang` and `RTL` in `src/lib/i18n.ts` (and to `resolveLang`'s auto rule).
2. Create `src/i18n/<code>.ts` exporting a `Catalog`; register it in `CATALOGS`.
3. Add the option to `LangSeg` in `src/views/Settings.tsx`; extend the coverage check in `scripts/i18n.test.ts`.

## RTL rules
- Use **logical** Tailwind utilities in the chrome: `ms-/me-` (not `ml-/mr-`), `ps-/pe-`, `start-/end-`, `border-s/e`, `rounded-s/e`, `text-start/end`. Physical ones stay only where they mean the physical side of a coordinate space (canvas, whiteboard, graph, PDF page overlays, chart axes, sliders driven by `clientX`).
- Inline styles: `insetInlineStart`, `marginInlineStart`, `paddingInlineEnd`.
- Slide-in sheets/drawers that use `translate-x` need an `rtl:` variant (`translate-x-full rtl:-translate-x-full`).
- Directional glyphs are mirrored globally by CSS (`src/index.css`, "Arabic interface"): lucide chevrons / arrows / undo-redo / indent / panel icons and the Lumen glyph `chevron-right`. Neutral glyphs (play, check, search, clock) aren't. Opt out with `className="no-flip"`. Chevrons turned with a `rotate-*` utility are not mirrored twice.
- Progress bars that fill with `width: x%` in normal flow fill from the right automatically; absolutely positioned fills must use `start-0`.
- **LTR islands**: `code`, `kbd`, `pre`, URL/email inputs and anything with class `.ltr` stay left-to-right. Note titles, file names and other user text get `dir="auto"` so an English title stays LTR inside the Arabic interface. Numbers in tables use `tabular-nums` and stay LTR.
- Arabic UI typography: IBM Plex Sans Arabic first, 14/22 (`:root[lang="ar"]` in `index.css`).
